# 机场自动化巡检管控系统调研报告

> 聚焦"管控平台 + 自动化机场/机巢"协同的无人机巡检系统
> 数据截至 2025 年 6 月，来源：民航局、招投标公开数据、厂商产品文档、行业公开报告

---

## 一、产品定义与系统边界

### 1.1 什么是"机场自动化巡检管控系统"

以**自动化机场/机巢**为前端节点、**管控平台**为后端大脑的分布式低空巡检系统，核心特征：

```
┌──────────────────────────────────────────────────────┐
│  云端管控平台 (SaaS/私有化)                              │
│  航线 / 任务 / 数据 / AI / 工单 / 3D 可视化             │
└────────────────┬─────────────────────────────────────┘
                 │ 4G/5G/光纤
    ┌────────────┼────────────┐
    ▼            ▼            ▼
┌────────┐  ┌────────┐  ┌────────┐
│机场1号 │  │机场2号 │  │机场N号 │  ← 分布式部署
│+飞行器 │  │+飞行器 │  │+飞行器 │
└───┬────┘  └───┬────┘  └───┬────┘
    │            │            │
    └────────────┴────────────┘
              巡检对象
   (电网 / 管线 / 道路 / 园区 / ...)
```

### 1.2 系统五大核心模块

| 模块 | 关键能力 | 技术指标 |
|------|---------|---------|
| 1. 机场/机巢管理 | 多机场接入、状态监控、远程升级、充换电调度 | 支持 ≥100 机场并发 |
| 2. 飞行任务管理 | 航线规划、任务派发、应急调度、协同作业 | 航线精度 ≤0.5m |
| 3. 飞行管控 | 起飞/降落/巡航控制、应急处置、空域申报 | 视距外（BVLOS）合规 |
| 4. 数据中台 | 图传/影像/激光点云/工单统一管理 | 海量数据存储检索 |
| 5. AI 智能识别 | 缺陷自动识别、风险预警、报告生成 | 准确率 ≥90% |

## 二、市场空间

### 2.1 核心数据

| 维度 | 数据 |
|------|------|
| 自动化机场/机巢 2024 中国出货量 | 数千台级别，**未来 3 年 CAGR 50%+** |
| 单机巢价格区间 | 5-15 万元（消费级）、20-50 万元（工业级）、80-200 万元（高端智能机场） |
| 管控平台年订阅价 | 5-30 万元/平台（按机巢数/功能模块计） |
| 招标案例 | 南方电网 2024 框架 8600 万；中国铁塔浙江 484 万；深圳深汕应急 160 万；义乌消防 99 万；某部舟山 94 万 |
| 国央企采购占整体 | **>70%**（电网、铁塔、消防、公安、应急） |

### 2.2 为什么这是优质赛道

- 从卖设备转向卖"机场 + 平台 + 服务"，客单价提升 5-10 倍
- 强复用性——一套平台可服务电网、油气、水利、应急、园区等多行业
- 数据资产沉淀——AI 识别模型随项目积累壁垒
- 政策直接拉动——民航局《固定设施设备巡检标准场景》(IB-FS-OPS-011) 2024 年发布

## 五、技术架构建议

### 5.1 部署模式

| 模式 | 适用客户 | 优势 |
|------|---------|------|
| 公有云 SaaS | 中小企业、园区 | 部署快、运维省 |
| 专有云（私有化） | 国央企、涉密客户 | 数据安全、定制化 |
| 混合云 | 大型集团 | 边缘 + 云端协同 |
| 纯私有化（信创版） | 政务、军工 | 等保 2.0/3.0、信创栈 |

> 重要提示：电网、油气、政务客户 **90% 要求私有化部署**，需提前规划国产化（麒麟 + 鲲鹏/海光/飞腾）。

### 5.2 技术栈选型（参考）

| 层 | 推荐技术 |
|----|---------|
| 前端 | Vue 3 / React + Three.js（3D）/ Cesium（GIS）/ Mapbox |
| 后端 | Spring Boot / Go / Python（AI） |
| 流媒体 | SRS / ZLMediaKit / GB28181 接入 |
| 数据库 | PostgreSQL + TimescaleDB（时序）/ MongoDB / MinIO（影像） |
| AI 框架 | PyTorch + Ultralytics YOLO / MMDetection / 自研 |
| 消息队列 | EMQX / Kafka / RabbitMQ |
| 地图 | 高德/天地图（合规）/ Cesium |
| 通信协议 | MQTT / RTSP / GB28181 / HTTP/WebSocket |
| 运维 | K8s + Prometheus + Grafana + 国产化适配 |

### 5.3 关键技术挑战

| 挑战 | 解决方案 |
|------|---------|
| 多机场协议适配 | 抽象设备层（Device Adapter），主流厂商 SDK 适配 |
| 海量影像存储 | 冷热分层（MinIO + 对象存储 OSS） |
| AI 模型快速迭代 | Model as a Service + 客户可训练 |
| 弱网/无网 | 边缘计算 + 断点续传 + 卫星回传 |
| 空域合规 | 与 UOM 平台对接，飞行动态实时上报 |
| 国产化 | 提前选型（操作系统、数据库、芯片、中间件） |

## 七、进入策略建议

### 7.1 产品策略：三阶段路线

**Phase 1（0-6 个月）：MVP 平台 + 单一行业突破**

- 选择 1 个行业深耕（推荐**电力或应急**）
- 兼容 2-3 个主流机场（必含大疆机场 2/3）
- 完成 1 个标杆案例

**Phase 2（6-18 个月）：多行业扩展 + 行业模型沉淀**

- 横向扩展到油气、水利、园区
- 沉淀 3-5 个行业 AI 识别模型
- 推出 SaaS 与私有化双版本

**Phase 3（18-36 个月）：平台化 + 生态化**

- 开放 API/SDK，建立生态
- 推出行业大模型、数字孪生
- 探索出海

### 7.2 商业模式建议

| 收入模式 | 占比 | 说明 |
|---------|------|------|
| 设备集成（机场+载荷+平台） | 40% | 一次收入，客单价 200-1000 万 |
| 平台订阅/年服务费 | 25% | 10-50 万/年/客户 |
| AI 识别服务（按调用量） | 15% | 0.1-1 元/图或按缺陷计费 |
| 运营托管服务 | 15% | 5-20 万/月/区域 |
| 数据增值/咨询 | 5% | 行业报告、数字孪生 |

### 7.3 竞争壁垒构建

1. AI 模型壁垒：行业缺陷数据（电网/油气/水利）
2. 协议兼容壁垒：主流机场/无人机品牌全覆盖
3. 场景化壁垒：3-5 个行业的 know-how
4. 国产化壁垒：信创栈、等保、密评
5. 生态壁垒：硬件厂商合作、央企联合实验室

## 十、关键洞察 & 风险提示

### 10.1 给从业者的 5 条核心建议

1. **不要只做平台**——客户要的是"机场 + 平台 + AI + 服务"一体化，纯平台价值会被硬件厂压缩
2. **抓住 2025-2026 国产化窗口**——电网/油气/应急大规模信创替换
3. **AI 模型才是真正护城河**——硬件会被价格战卷死，算法 + 数据不会
4. **私域化交付能力是关键**——90% 央企客户要私有化，必须有完整工程团队
5. **早期绑定 1-2 个央企**——标杆案例比什么都重要

### 10.2 风险点

- **大疆生态挤压**——大疆机场 2/3 + 司空 2 平台可能把控硬件入口
- **央企自研**——电网/油气管网自研系统挤压第三方空间
- **AI 模型同质化**——基础缺陷识别同质化严重，需深耕行业 know-how
- **回款周期长**——央企项目 6-12 个月回款，需充足现金流
- **数据安全责任**——一旦发生数据泄露或失控，将面临严重监管
